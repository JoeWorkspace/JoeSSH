# JoeSSH UI 评审与基线交付

日期：2026-07-29

## 结论

JoeSSH 已具备一套统一、可版本化的 Desktop、Web Admin、Mobile UI
基线。视觉语言统一为 graphite/cool-white 表面、emerald 主色和克制的状态色，
并覆盖浅色、深色、高对比度、减少动效、RTL、触控与键盘使用场景。

本轮“完整 UI”指覆盖仓库当前已经实现的产品能力。它不能替代尚未实现的产品
能力，例如 Web Admin 的写操作、Mobile 的完整 SSH/SFTP 客户端或生产身份认证。
“永久使用”被落实为可持续扩展的设计系统、响应式契约、测试门禁和视觉基线，
而不是冻结界面不再演进。

## 当前产品成熟度

### Desktop

Desktop 是当前功能最完整的客户端，覆盖连接库、终端标签、命令与搜索、分屏、
录制状态、SFTP、团队访问、端口转发、设置、导入导出、分组、快捷键、上下文
菜单、错误恢复和全部主要覆盖层。

本轮补齐了侧栏可见折叠与恢复、名称/主机/标签/用户名/原始及本地化分组搜索，
以及自定义连接的用户名、端口、范围校验和持久化。Desktop 的浏览器预览仍会
明确标注示例数据；真实 SSH、SFTP 和端口转发能力依赖 Tauri 原生运行时。

### Web Admin

Web Admin 已覆盖同步健康、快照来源、成员、角色、设备、审计、加载、鉴权、
空数据、不可用、格式错误、过期与就绪状态，并具备移动导航、打印、语言与
遥测控制。

当前产品边界仍是只读运营台，不包含成员、角色或设备的创建、编辑、撤销等
管理写操作。因此 UI 已覆盖现有功能，但它还不是完整的可变更管理后台。

### Mobile

Mobile 已覆盖语言、设备注册、register → push → pull、游标、预览指标、在线/
离线/超时/未授权/未知错误、应急通道、系统深浅主题、安全区、RTL 与致命错误
恢复。320px 手机与 768px 平板均有明确布局。

当前产品边界仍是同步与应急访问 companion，不是完整 SSH/SFTP 客户端。生产
身份认证和完整远程会话能力仍需后续产品开发。

## 本轮 UI 基线

- 共享语义 token 与 Button、IconButton、Badge、Panel、SegmentedControl 状态。
- Desktop 全功能主题、三栏/下置上下文/单栏断点、短高度与 200% 缩放布局。
- Web Admin 固定导航、指标卡、数据表、移动横向导航与 320px 表格边界。
- Mobile 品牌 Hero、状态卡、终端预览、应急卡片、手机/平板与 RTL 布局。
- 所有关键状态不只依赖颜色表达；主要交互具备 focus、pressed、disabled、
  busy、error 和 offline 表现。
- 中英文 Desktop/Web/Mobile 视觉快照已更新，Visual QA CI 与 Windows 快照
  平台已对齐。

详细设计与扩展规则见 `docs/ui-system.md`。

## 本轮生产终审新增修复

- 修复共享 UI 和 Desktop 在“系统 Light + 显式 Dark”时被媒体查询反向覆盖，
  现在用户显式主题始终优先于操作系统主题。
- 修复 320px 经典滚动条环境下共享 `body` 最小宽度造成的横向溢出，并加入
  回归测试。
- 修复 Desktop 多层覆盖层的 Escape 冒泡、焦点恢复、分组重命名提交与残留
  状态问题。
- 修复 Web Admin 在 761/911px 的六列表格裁切、320px 审计日志重叠、移动导航
  聚焦可见性、锚点遮挡、打印宽度、列表/landmark 语义和三级文本对比度。
- 修复 Mobile 生产构建错误解析到测试版 `react-native` mock 的问题；真实
  Safe Area 组件现已加载，并有生产模块解析契约测试。
- Mobile RTL 改为跨原生端稳定的行反转与物理左右强调边框，覆盖 Arabic
  `fontScale=2`；弃用的 shadow/pointerEvents 写法已迁移为 RN 0.82 支持的
  `boxShadow` 与 `style.pointerEvents`。
- Mobile Web 会随当前语言同步页面 `lang`，并对无 `document` 的原生运行时
  安全降级。
- 修复 Mobile live E2E 模拟服务的过期 pull 响应，使完整注册、推送、首次拉取
  和基于 `server-42` 游标的第二次增量拉取均按当前严格同步契约通过。
- 补齐 15 种语言的演示数据、未连接会话和安全操作提示，消除非英语界面中的
  英文泄漏；错误遥测统一改为更清晰、面向用户的“可选错误报告”。
- 移除 Desktop 终端面板中没有对应行为的“更多”按钮，避免出现无法执行的
  伪交互入口。

## 发布与后续边界

### 已解决：源码控制基线

本轮 UI 已迁移到基于 `origin/main` 的健康 clone，并在该基线上完成差异复核、
构建、功能 E2E 和视觉 E2E。原元数据损坏的工作区不再作为提交或发布源。

### P0：Mobile 依赖栈不一致

当前 Expo 56 与 React Native 0.82.1 / React 19.1.1 混用；Expo 56 的目标栈是
更新的 React Native/React 组合。Web export 可以成功，但 Android export 在
Hermes bytecode 阶段因 private class fields 失败。应单独安排依赖对齐升级，
并在 Android/iOS 真机重新执行完整回归。

### P1：原生设备验收

浏览器等效缩放不能替代打包后的 Tauri DPI、移动字体缩放、真实 safe area、
平台屏幕阅读器、键盘法与 Android/iOS 真机测试。这些仍是发布门禁。

### P2：已存在的体积告警

Desktop 构建中的 xterm chunk 约 289 kB，超过 Vite 的 250 kB 提示阈值，但
不影响本轮构建通过。后续可评估懒加载或独立 chunk 策略。
