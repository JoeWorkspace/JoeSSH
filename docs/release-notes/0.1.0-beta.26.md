# JoeSSH 0.1.0-beta.26 Source Preview and Microsoft Store Maintenance Candidate

JoeSSH `0.1.0-beta.26` is prepared as a source-only GitHub prerelease and the
source revision for a separate Windows x64 Microsoft Store maintenance update.
The intended GitHub Release provides automatically generated source archives,
does not include Desktop installers, and has zero uploaded assets. Version
preparation does not establish that a tag, Release, or binary has been
published.

The candidate maps to MSIX `1.1.26.0`, following the existing published
`1.1.22.0` Store package. The `1.1.23.0` and `1.1.24.0` qualification attempts
remain superseded. The beta.25 `1.1.25.0` strict qualification run returned a
required WACK Requirement 26, TEST 92 `DPIAwarenessValidation` warning. That
package and its source-build, hosted-candidate, native, WACK, lifecycle, and UI
evidence remain immutable, are superseded, and cannot be submitted or reused to
approve beta.26.

A new package must be built from the exact protected `main` revision carrying
beta.26 and pass source binding, clean-machine lifecycle, WACK, visual review,
and Partner Center certification. Its expected filename begins with
`JoeSSH_1.1.26.0_x64_` and includes the source commit and workflow-run binding.

## Included fixes

- The Windows build bypasses `tauri-winres` inline-manifest serialization,
  which added whitespace around each serialized line. Tauri's default
  application manifest is disabled, and Windows Resource Compiler embeds the
  reviewed BOM-less UTF-8 source bytes directly as the executable's sole
  `RT_MANIFEST/#1` resource.
- The Store source build parses the compiled PE32+ resource table directly. It
  requires exactly one type 24 / ID 1 / en-US 1033 manifest resource, requires
  the first byte to be `<`, rejects a BOM or leading byte, and proves exact
  source-byte equality before and after the MSIX pack/unpack round trip.
- The existing XML semantic and Windows SDK `mt.exe` validation remain in
  place. They supplement the raw PE gate and cannot replace it.
- The beta.25 fixes remain in the source tree: the Store Desktop build omits
  the unused Windows self-relaunch path, terminal safety checks reject
  downloaded or decoded content piped into a remote program, vendored Tauri
  inputs stay checksum-bound, and the shared Mobile preview graph retains the
  patched linear-time URI decoder.

## Delivery and product boundaries

- Product identity remains Microsoft Store `9NK5LLMF8LHM`, Windows x64.
- The package continues to declare 15 complete UI locales. Store listing
  locales remain discoverability metadata and are not additional installed UI
  translations.
- Desktop, Web Admin, Sync Service, and Mobile version surfaces advance
  together to `0.1.0-beta.26`; this Store-only delivery does not publish
  separate Web, Sync, or Mobile binaries.
- New build evidence, legal notices, SBOMs, SHA256 checksums, and native
  verification evidence must bind the exact beta.26 candidate commit and MSIX
  bytes. No beta.23, beta.24, or beta.25 package or evidence can approve
  beta.26.
- Microsoft certification and Store publication remain separate from source CI
  and local package generation. A version bump is not publication evidence.
- The full Desktop/Web/Sync Service public-release gate is not waived.
  `release:publish-preflight` remains blocked until a distinct multi-platform
  release has complete evidence. Mobile remains in preview, Web Admin remains
  read-only, and this update adds no hosted or paid service.

Automated accessibility coverage does not extend the historical manual
assessment. There is no WCAG, EN 301 549, or EAA conformance claim.

## Microsoft Store What's new draft

Improves Microsoft Store high-DPI package compatibility by embedding the
reviewed UTF-8 Windows application manifest directly as the executable's sole
`RT_MANIFEST/#1` resource and verifying its raw bytes before and after MSIX
packaging. This is a new `1.1.26.0` candidate; build qualification,
certification, and publication remain pending.
