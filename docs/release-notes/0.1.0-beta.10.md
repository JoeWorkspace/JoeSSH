# JoeSSH 0.1.0-beta.10 Release Candidate

JoeSSH 0.1.0-beta.10 is the Windows-first release-preparation candidate. It is
not approved for public or paid distribution until every item under
`Release blockers` is closed with real external evidence.

## Highlights

- Completes the shared JoeSSH visual system across Desktop, Mobile, and Web
  Admin, including light and dark themes, responsive layouts, Windows scaling
  coverage, accessibility checks, and visual-regression baselines.
- Expands the Desktop workbench with a clearer first-run path, connection and
  group management, resilient workspace persistence, terminal search and
  shortcuts, SFTP safety, port-forward lifecycle handling, and localized
  operational surfaces.
- Adds a commit-bound Windows invite pipeline. Stage A can package and promote a
  private unsigned candidate for a small trusted test group; Stage B remains
  fail-closed until authentic signing, timestamping, Defender, reviewer, and
  independent promotion evidence exist.
- Rebuilds the npm dependency graph for cross-platform lockfile portability and
  adds a regression gate for incomplete optional-platform metadata.
- Hardens public vulnerability reporting, repository ownership, secret scope,
  dependency auto-merge, and high-privilege GitHub Actions behavior.
- Adds a redacted full-history secret scan whose reviewed fixture exceptions
  are bound to exact historical fingerprints and cannot be widened silently;
  CI installs SHA-256-verified Gitleaks 8.30.1 and runs the real scan.
- Adds separate Windows Store EXE and external-MSIX preparation paths,
  plus a hosted-only two-job verifier that requires an external artifact URL
  and SHA-256 while keeping signing authority, local builds, and handoff files
  outside the workflow. It does not claim that an external store, payment
  processor, or seller account has been approved.

## Release scope

- The first revenue-validation lane is JoeSSH Desktop on Windows 10/11 x64.
- Community SSH, SFTP, port forwarding, host-key verification, and core safety
  behavior remain free and open source.
- Mobile public distribution, hosted Sync, team SaaS, paid SLA, macOS
  notarization, and Linux commercial distribution are outside this candidate's
  paid support promise.
- The self-hosted Sync Service and Web Admin remain evaluation/community
  surfaces and must not be marketed as a production hosted service.

## Free Community Store blockers

- Resolve the truthful Partner Center account type under current Store policy,
  enroll the verified publisher without using the placeholder-like
  `JoeSSH Project`, and reserve the Store product identity. A solo commercial
  publisher still uses the Company path and supplies real business
  verification; Individual is only for genuinely noncommercial publishing and
  cannot later be converted in place.
- Time-box a one-day Microsoft MSIX Packaging Tool feasibility spike after the
  Partner Center identity is available. Run WACK and exercise SSH, PTY, SFTP,
  local forwarding, WebView2, install, update, uninstall, and rollback. If it
  passes, submit the exact SHA256-bound package so Microsoft Store can re-sign,
  host, and update the free Community app; Tauri does not natively produce
  MSIX.
- If the MSIX spike exposes a documented compatibility blocker, fall back to a
  Tauri NSIS EXE produced outside the repository workflow through an
  independently controlled public-trust signing path. Host it at an immutable,
  versioned HTTPS URL and use the no-signing-authority hosted verifier to bind
  its timestamp, installed payload signatures, reviewed source, and exact
  SHA-256 to the submission. The workflow defaults to MSIX and rejects an EXE
  dispatch without a bounded, non-placeholder MSIX fallback justification.
- Complete Stage B signing or Store-signing status, Defender, native smoke,
  install, upgrade, uninstall, rollback, clean-VM, and independent promotion
  evidence.
- Configure the protected `main` branch and release environments after the
  repository plan/visibility supports those controls.
- Confirm the public vulnerability-reporting path while signed out after the
  repository is made public and private vulnerability reporting is enabled.
- Configure real seller, support, and privacy values and logged-out HTTPS
  pages; placeholders or templates are not publishable.
- Complete candidate-bound Store screenshots, required Store art, Markets,
  Discoverability, privacy declarations, and certification notes.
- Confirm GitHub Actions billing/spending-limit state and reduce the current
  cache footprint before generating formal evidence.
- Pass `npm run qa:release-preparation`,
  `npm run qa:windows-store-release`, and
  `npm run qa:windows-store-surfaces:runtime` on the exact candidate commit;
  then pass the hosted candidate verifier and Partner Center certification.

## Voluntary-support validation

- Validate a real voluntary-support page, account ownership, logged-out access,
  a small payment, refund/non-purchase wording, and payout before enabling the
  funding link. Bind the exact URL and all five checks to a current, non-secret
  `.github/funding-operator-attestation.json` so ordinary Community QA/CI stays
  green without one-off confirmation flags.

## Future paid-release blockers

- Reach at least 10 repeat users and 5 real supporters before applying to a
  merchant of record or building a non-selling Founder/Pro prototype.
- Reach the stronger paid launch threshold, obtain product-category and payout
  approval, configure real refund, terms, seller, checkout, and customer-portal
  values, and test purchase, delivery, recovery, cancellation, refund, failed
  payment, and payout. JoeSSH port forwarding must be disclosed in provider
  review.
- Keep checkout disabled until every paid commercial gate passes.

The full `npm run release:publish-preflight` remains mandatory only when
publishing the complete Desktop/Web/Sync multi-platform GitHub Release. It is
not a shortcut or prerequisite for the independent Windows-first Store
candidate path.
