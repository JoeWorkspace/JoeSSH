# JoeSSH 0.1.0-beta.30 Store maintenance candidate

This update integrates the reviewed terminal, forwarding and release checks on
the beta.29 main baseline, `312811c070790e1bb04bf164214e1db97a3f8825`.
It uses a new Microsoft Store package version, `1.1.30.0`; earlier package bytes
and qualification evidence cannot be reused for this source revision.

## Changes

- Recover the native shell when a legacy PWA worker serves a stale startup
  entry. Early native initialization removes only the application's old worker
  and known static caches, preserves saved connections and trust data, and
  prevents native worker registration. Browser PWA offline support remains.
- Preserve terminal sizing and forwarding state across workspace changes and
  reject duplicate starts.
- Bound editable PTY input before dispatch while preserving host-key checks,
  credential handling, output backpressure and connection deadlines. Local input
  preflight does not authorize commands on a remote host.
- Reject escaped, linked, replaced or mismatched release artifact paths and
  malformed or incomplete dependency audit reports.
- Update compatible dependency fixes, including Tokio 1.54.1 for
  RUSTSEC-2026-0386, and apply the independently reviewed Node-only node-forge
  backport described in [its maintenance record](../node-forge-backport.md).
  Upstream node-forge 1.4.0 still has a high advisory; the gate verifies the
  original registry identity and exact repaired source, and blocks unknown
  findings. This is not an upstream fixed release or a high-severity waiver.
- Close E2E browser contexts on failure and preserve failure traces. Test
  assertions and release thresholds remain in force.

## Release boundary

The distribution target is Microsoft Store MSIX. Microsoft signs packages
through Store certification; a private Authenticode certificate and Apple
credentials are not prerequisites for this path. No direct installer or macOS
release is included.

Source checks and the completed local 78-case E2E run are regression evidence.
The exact merged source still requires all protected CI checks, a new hosted
source build and candidate verification, fresh legal evidence, isolated Windows
native qualification and the actual Store submission. These notes do not assert
certification, publication or real-device acceptance.

Any future GitHub record must be a source-only GitHub prerelease with
automatically generated source archives and zero uploaded assets. It does not
include Desktop installers and makes no WCAG conformance claim. Keep the Store
artifact and its source, hash, workflow and provenance records distinct.

The broader public release checklist covers Desktop, Web Admin and Sync Service.
Any binary release must carry SHA256 evidence and pass
`release:publish-preflight`; this Store maintenance candidate does not publish
Web Admin or Sync Service binaries.
