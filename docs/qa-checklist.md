# JoeSSH QA Checklist

## Sync Service

- `GET /healthz` returns `200` and includes service name, version, and timestamp.
- `GET /readyz` returns `200` for process-local memory storage or writable JSON ledger storage, and returns `503` without exposing local filesystem paths if configured JSON ledger storage becomes unwritable after startup.
- Device registration accepts `desktop`, `web`, `ios`, and `android` platform values.
- Push rejects empty change sets with `400`.
- Push accepts non-empty change sets and returns an advanced cursor.
- Pull returns a stable `next_cursor` and no duplicate changes for the same cursor window.
- Idempotency is verified for repeated `changes[].id` submissions.
- Pull returns remote changes after `since` while excluding the requesting device's own changes.
- Stale-base pushes report entity conflicts instead of overwriting newer server changes.
- `GET /healthz` remains unauthenticated, while configured `ATLASTERM_SYNC_AUTH_TOKEN` gates all `/v1` sync traffic.
- Default sync CORS does not emit browser allow-origin headers; `ATLASTERM_SYNC_CORS_PERMISSIVE=1` is reserved for loopback local development and fails startup on non-loopback binds.
- Environment-provided sync/admin bearer tokens must be at least 32 characters, contain no whitespace/control characters, and be distinct.
- `ATLASTERM_SYNC_CORS_ORIGINS` accepts only HTTP(S) origins, restricts browser origins, and allows `Authorization`/`Content-Type` preflight headers before non-local deployment; it must not be combined with permissive CORS.
- `GET /v1/admin/snapshot` returns a Web Admin-compatible snapshot derived from the current sync ledger; it requires a dedicated `ATLASTERM_SYNC_ADMIN_TOKEN` distinct from the regular sync token, rejects the regular sync token with `403 admin_forbidden`, and fails closed with `403 admin_token_required` when the admin token is missing or reused.
- Sync registration and push requests reject fields that would make Web Admin snapshots malformed: `app_version` and optional `display_name` must be bounded, nonblank, trimmed, and free of control/Unicode format characters; `entity_type` and `entity_id` must be bounded canonical sync entity tokens before any change is accepted.
- `ATLASTERM_SYNC_RATE_LIMIT` configures per-client per-second request rate limiting (default: 100 req/s), rejects invalid values at startup, and accepts `0` only when an upstream proxy enforces rate limiting.
- `ATLASTERM_SYNC_STORAGE_PATH` enables the single-process JSON ledger, persisting `schema_version: 1`, registered devices, processed change IDs, accepted changes, and the latest cursor across service restarts.
- `ATLASTERM_SYNC_MAX_PUSH_CHANGES`, `ATLASTERM_SYNC_MAX_PULL_CHANGES`, `ATLASTERM_SYNC_MAX_STORED_CHANGES`, and `ATLASTERM_SYNC_MAX_LEDGER_BYTES` bound JSON ledger growth and pull page size; invalid or zero values fail startup, oversized existing ledgers fail startup before serving traffic, over-quota register/push requests return `413 ledger_quota_exceeded` while rolling back in-memory changes, and zero pull `limit` returns `400 invalid_sync_request`.
- JSON ledger `changes` remains complete sync history for paginated `pull since=0` and slow-device recovery; pull paging advances `next_cursor` over the scanned sequence window, does not skip filtered self changes, and requires clients to continue while `has_more` is true; `audit_log` is bounded operational history for recent Web Admin events and is compacted before persistence.
- Non-loopback Sync binds require sync bearer auth, metrics bearer auth, durable JSON ledger storage, and scoped CORS; `ATLASTERM_SYNC_ALLOW_EPHEMERAL_STORAGE=1` is only a short-lived evaluation escape hatch and must not be used for Public Beta self-hosted deployments.
- JSON ledger startup migrates legacy v0 ledgers that have no `schema_version`, and rejects future `schema_version` values before serving traffic.
- JSON ledger startup prepares the configured storage directory before serving traffic, acquires a `ledger.lock` single-writer guard, and fails fast if either step is not usable; `npm run qa:sync:config-guard-smoke` proves a non-loopback bind without metrics auth fails startup, proves a non-loopback bind without durable storage fails startup, proves a non-loopback bind with an unusable storage path fails startup, proves a non-loopback bind with permissive CORS fails startup, then proves a second service instance cannot use the same ledger while the first instance remains healthy, and docs explain stale-lock cleanup after host crashes.
- JSON ledger startup recovers from a valid `.bak` file when the primary ledger is missing or unreadable, and uses a complete `.tmp` file only when neither primary nor backup exists.
- Public Beta backup/restore smoke runs with `npm run qa:sync:backup-restore-smoke`, copying an operator ledger backup, corrupting the primary ledger, restoring through `.bak`, verifying pull/admin snapshot recovery, and checking backup recovery metrics with measured RPO/RTO. Packaged release evidence must come from the staged packaged lane below.
- Packaged Sync backup/restore release candidates must pass `npm run qa:sync:release-backup-restore-smoke`, binding the backup/restore drill evidence to the staged release binary path, that binary's sha256, and the checksum manifest.
- Register and push mutations return `503 storage_unavailable`, roll back in-memory changes, and ensure the same change ID can be retried if configured JSON ledger persistence fails; ledger quota rejections return `413 ledger_quota_exceeded` before acknowledging over-large pushes or over-capacity ledgers.

## Desktop Workbench

- Terminal panes render with LTR terminal content under LTR and RTL UI locales.
- Terminal session rendering uses structured line IDs so repeated command text does not collide or reorder in React.
- Terminal command input accepts safe commands through the local safety preflight before they reach the session log.
- One-shot `ssh_exec` command output is capped at 1 MiB in the core SSH read loop, and Tauri maps output-limit failures to a stable renderer-safe error instead of buffering unbounded stdout.
- Dangerous terminal commands such as `sudo rm -rf /` are blocked with an accessible policy alert and are not appended to the session log; the native Tauri `ssh_exec` IPC boundary also runs the core command-safety blocklist before opening the session, and `pty_write` applies the same line-level blocklist before forwarding submitted PTY input, so direct renderer IPC cannot bypass the local preflight. Native `PTY_COMMAND_BLOCKED` rejections are surfaced in the xterm status bar as an assertive alert and the PTY remains open for the next safe command.
- Command palette, SFTP, settings, team access, shared vault, and audit context flows remain keyboard and screen-reader reachable.
- SFTP upload/download uses a 25 MiB per-operation safety limit; the UI refuses known oversized remote downloads and local uploads before allocating file bytes where possible, remote listing entry names must pass safe single-segment validation before navigation/download/upload path joins, the core SFTP downloader enforces the cap before and during remote reads, and the Tauri backend rejects oversized upload IPC payloads before writing.
- Team access review flow opens from the Review action, supports keyboard approval/rejection, updates pending JIT state, and records an audit event.
- Connection Move to group actions persist validated per-connection group overrides and survive reload without mutating the base connection catalog.
- Connection drag ordering persists validated per-connection order and survives reload without dropping newly added default connections.
- Terminal command history supports repeated ArrowUp/ArrowDown traversal through prior accepted commands.
- Desktop real SSH dogfood runs in CI with `npm run qa:desktop:real-ssh-smoke`
  against a loopback OpenSSH fixture with `JOESSH_REAL_SSH_SMOKE=1`, covering
  host-key probe and pinned trust, password authentication, exec, PTY output,
  SFTP list/download/upload/overwrite, local `direct-tcpip` forwarding, and
  forward shutdown through the same Rust core used by the Tauri shell.
